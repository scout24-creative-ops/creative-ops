The older LP Builder runtime styles remain necessary for existing AEM pages and must stay backward-compatible, but they should not become the styling basis of the new Contentful module library.

### 2026-09-04 — Asset migration layer prepared before S3 provisioning

Before scaling the remaining Anwenderhandbuch pages, Dominik decided to prepare the asset migration layer even though the planned S3/CDN target is not being provisioned yet. The goal is to avoid coupling migrated pages permanently to legacy AEM asset URLs and to make a later host switch possible without reinterpreting page content.

Codex audited the existing migration data and found 221 asset references across the 57 migration-ready packages, representing 210 unique normalized source URLs. Existing data already includes source URL, local package asset IDs, block/page references, DOM paths, ordering, alt text/caption data and validation observations such as reachability, final URL, HTTP status, content type/length and redirects. The audit also confirmed that the existing `content_hash` values are block hashes rather than byte hashes and therefore must not be reused as physical asset hashes.

A central local asset SSOT was then created under `migration/assets/`: `manifest.json`, a generated `manifest.csv` view, `README.md`, and the reproducible local generator `scripts/build_b2b_asset_manifest.rb`. The manifest currently contains 210 entries and consolidates 11 duplicate references by normalized source URL. It uses temporary global import IDs of the form `src-<sha256(normalized-source-url)>`; final `ast-sha256-*` IDs remain intentionally empty until actual files are downloaded and byte-hashed. `target_key` and `target_url` are also still empty because no S3/CDN target exists yet.

Current manifest status is 102 reachable, 94 unreachable and 14 unknown entries. Twenty-three manifest entries have a source alt text and 187 do not. Fourteen AEM URLs contain a `{width}` placeholder, two consolidated URLs carry conflicting historical reachability observations, and one repeated reference points to the same block reference. These are explicitly preserved as observations rather than guessed away.

The planned future model is: source content references a stable manifest identity; today that identity resolves to the legacy source URL, later it resolves to a verified S3/CDN target URL. Final asset IDs should be based on the full file SHA-256, with a target-key pattern such as `assets/sha256/<first-two-hex>/<full-sha256>.<verified-extension>`. Physical deduplication must be based on identical file hashes, never filename alone. No new page crawl is required for this model; only a later targeted asset download/validation pass is needed to obtain real file hashes, dimensions and verified file types.
