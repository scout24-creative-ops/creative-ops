### 2026-09-01 — CoreCSS/COSMA-first direction verified for static LP Builder HTML

Dominik verified an important technical direction for the new Contentful Builder. The `is24-cms-frontend` globally loads `is24-corecss` 9.2.0, `is24-corecss-server` 9.2.0 and `@is24/cosma-ui-icons` 6.24.0 under the COSMA theme. Repository inspection confirmed that many CoreCSS classes are used directly on normal HTML elements rather than only through React components.

This materially simplifies the Builder architecture: static `htmlSource` can reuse the existing Scout24 design-system layer instead of recreating a separate CSS world. Verified native families include typography (`font-heading-*`, `font-body-*`), spacing (`margin-*`, `padding-*` variants), grid/responsive layout (`grid`, `grid-flex`, `grid-item`, `one-*`, `palm-*`, `lap-*`, `desk-*`, gutter variants), standard buttons (`button-primary`, `button-secondary`), several basic utilities and the COSMA icon font (`s24-icons-*`).

The current strategic rule is therefore **CoreCSS/COSMA first**. Own LP Builder CSS should only cover the real delta that static HTML cannot express through the globally available system, for example selected media behavior, surface/radius combinations or module-specific layout. Any such bridge should use existing COSMA design tokens rather than introduce a parallel design system.

The older LP Builder runtime styles remain necessary for existing AEM pages and must stay backward-compatible, but they should not become the styling basis of the new Contentful module library.

### 2026-09-01 — LP Builder renderer behavior and Accordion bridge clarified

The Contentful LP Builder renderer sanitizes and injects `htmlSource` as static HTML inside the React application. Static HTML is therefore not automatically converted into ordinary Contentful React components, but it does inherit the globally loaded CoreCSS/COSMA styles.

For Accordion there is already a dedicated LP Builder interaction bridge in the frontend. The renderer initializes HTML using `.accordion`, `.accordion__item`, `.accordion__trigger`, `.accordion__panel` and `.is-open`, and manages expanded state, ARIA attributes and panel height. This means the migration-focused Builder does not need to recreate Accordion JavaScript; only its final HTML/styling contract needs to be aligned.
