# AI Enablement

## Purpose

Establish a binding AI enablement series for Marketing & Communications that combines shared learning with the development of concrete agents and workflows that create practical value for the participating teams.

The series is intended to raise practical AI maturity across the unit, create orientation and visible progress, connect existing expertise and move from decentralized experimentation toward a smaller number of reusable and strategically relevant solutions.

## Current Status

The project was initiated through alignment between Jorin Verges and Dominik Böhme on 2026-07-21 following the Marketing AI Landscape Check.

Jorin asked Dominik to develop the concept during Jorin's vacation and confirmed him as the fachlicher Lead for the topic through expertise, enablement and influence without operational people-management responsibility.

A first concept direction has been developed. The current proposed structure is:

1. Kick-off with strategic framing, the AI Team-Check results and an overview of the series.
2. One joint agent session in which the group learns how ideas are found, how an MVP is reduced and how a first shared update agent can be built and used.
3. Bilateral or small-group alignment by Dominik with relevant colleagues and teams to agree who will work on which agent or workflow.
4. One presentation session in which all assigned agent and workflow initiatives, owners or groups and first MVPs are made visible.
5. A recurring series combining one selected AI topic with short progress updates from every active person or group.
6. A later consolidation step to evaluate, combine, continue or stop initiatives and identify a small number of strategically relevant agents or workflows.

The concept is still being refined and has not yet been aligned with Jorin after his return.

## Working Model

- Every participating person or group works on a concrete agent or workflow that should create value for the relevant team or work context.
- Existing initiatives such as the Brand Agent or Chart Agent continue as real project work rather than being replaced by artificial workshop exercises.
- Colleagues without an existing idea receive prepared agent or workflow suggestions that can start with a small MVP and expand later if useful.
- The actual development work takes place between the recurring sessions, individually, in small groups or in existing project setups.
- Dominik accompanies the initiatives and provides guidance where needed without becoming the permanent builder or operational project manager for every agent.
- In the recurring sessions, every active person or group gives a short update on the progress of their agent or workflow.
- A shared slide structure and a planned update agent should standardize the update process and reduce preparation effort.
- Progress should not be treated as a competition or precise percentage. Useful progress can also mean reducing scope, validating a blocker, rejecting an assumption or stopping an unhelpful direction.

## Proposed Session Structure

### Kick-off

- Strategic relevance, commitment and protected time introduced by Jorin
- How AI changes work and how the unit can actively shape that change
- Findings from the AI Team-Check
- Overview of the objective and planned structure of the series

### Joint Agent Session

- Practical introduction to finding useful agent ideas
- Explanation of the MVP principle
- Shared update-agent use case
- Joint creation of a directly usable first update-agent MVP
- Preview of the following alignment of individual agent and workflow initiatives

### Initiative Alignment and Presentation

Before the presentation session, Dominik aligns with relevant colleagues and teams to identify existing initiatives, reduce ideas to practical MVPs, prepare suggestions where no idea exists and clarify ownership or group setup.

The following shared session then presents:

- all existing and new agent or workflow initiatives
- the responsible individuals or groups
- the objective and first MVP of each initiative
- the shared documentation and update approach

### Recurring Series

Each recurring session combines:

- one selected AI topic, agent demo or practical experience report led by Dominik or another contributor
- short updates from every active person or group on the current state of their agent or workflow

The development work itself happens between the sessions. The recurring format creates shared learning, visibility and commitment.

### Consolidation

After a defined working phase, the initiatives are reviewed separately from the regular update rhythm. The review should identify local solutions, reusable components, overlapping initiatives, candidates for team-wide or unit-wide scaling and initiatives that should be stopped or merged.

## Update Slides

The current direction is to use a small standard slide set per initiative:

1. A stable definition slide for the agent or workflow, including the problem, users, purpose and first MVP.
2. A recurring update slide showing the current MVP stage, meaningful developments since the last session, learnings, blockers and next step.

For multi-agent workflows, the first slide can describe the overall workflow and participating agents. Separate update slides should only be added for individual agents where they are useful.

## Decisions and Working Assumptions

- Treat AI Enablement as a separate ongoing project from the AI Team-Check.
- Use the AI Team-Check findings as input and rationale, not as the project container for the series.
- Use a binding recurring format with leadership backing and protected time.
- Do not use the large recurring sessions as live build workshops.
- Keep the recurring session structure simple: one focused learning topic followed by updates from all active initiatives.
- Use real ongoing agent and workflow initiatives wherever possible.
- Prepare useful agent or workflow suggestions for colleagues who do not yet have a suitable idea.
- Align initiative assignments before the shared presentation session rather than negotiating all assignments in the large group.
- Use a dedicated longer session for the shared update-agent MVP instead of distributing its build across multiple meetings.
- Keep the operating model lightweight and avoid creating unnecessary coordination work for Dominik.

## Risks and Open Questions

- Final participant scope and whether team leads participate directly.
- Exact cadence and duration of recurring sessions.
- Number of individual initiatives and resulting total update time.
- Final method for selecting suitable agents or workflows for each person or group.
- Final slide templates and update-agent behavior.
- How much protected working time participants receive between sessions.
- How progress, participation and stalled initiatives are handled without turning the format into a ranking or control exercise.
- Final criteria and decision process for consolidation and strategic continuation.
